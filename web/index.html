Every pull request is benched on all five profiles against a baseline built from the same commit on the same runner, three passes per workload, median reported. Single-profile swings inside 15 percent are treated as noise and labelled as such. Read the method.

Reads never wait for writers

Snapshot isolation with multi-version reads. A query sees one consistent moment in time and takes no locks, so a long read cannot be blocked by a slow commit and a slow commit cannot be blocked by a long read. Read p99 stays under a millisecond on Linux even while writers are syncing.

Writes are the honest problem

A commit returns once its record is on disk. Concurrent writers share one sync through a group commit coordinator, and the group closes early when the queue goes quiet. That took 2 CPU writes from 3,036 to 8,374 operations per second. PostgreSQL is still ahead and the remaining distance is almost entirely the durable commit itself.

Corruption is detected, not assumed away

Every page carries a CRC32 and its own identity, verified on each read. Pages are never written before their log record is durable, so recovery replays whole batches only. A crash exposes all of a commit or none of it. There is no faster mode that quietly drops this.

Six crates, one direction

The dependency graph is acyclic and enforced. Parsing knows nothing of storage, the server delegates everything to the engine, and the network threads never touch a disk. Each layer is tested alone, and a concurrent history checker runs against the whole thing.

Get started

There is no published image yet, so the quickstart builds from source. The server speaks one protocol: JSON frames, one per line, over TCP on port 6626.

The protocol is deliberately boring so a young database stays debuggable: you can drive it from a terminal and read every byte that crosses the socket. It is documented frame by frame in protocol-v1.

Where this actually is

QuantaDB is experimental. Do not put data you care about in it. The milestones are numbered because each one is load bearing for the next.

  1. Done

    Syntax and server foundation

    Span-aware parser, versioned protocol, bounded connections.

  2. Done

    Durable storage kernel

    Checksummed pages, two-segment WAL, group commit, crash recovery.

  3. Now

    Transactions and indexes

    MVCC snapshots and online B+ tree generations are in. Range conflict tracking and the remaining write throughput gap are open.

  4. Next

    Execution engine

    Planner, joins, ordering, secondary indexes, cost-based decisions.

  5. Next

    Production operations

    Authentication, TLS, backup, and a stable on-disk format.

  6. Next

    Replication

    Replicated log and failover, with adversarial failure testing.

There is no authentication, no authorisation, and no TLS on any listener. Anything that can reach the port can read and write everything. This is documented rather than fixed, for now.

QuantaDB is Apache-2.0 and developed in the open.
